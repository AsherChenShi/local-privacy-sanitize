# 个人使用场景审查与实施日志

2026-11-24 · 基线 `5eb7024` · 本轮 `0.2.6`

## 审查结果

| 使用场景 | 基线表现 | 优先级与处理 |
| --- | --- | --- |
| 临时处理一段提示词、日志或配置 | 要为一条消息创建输入文件、选择新输出目录，再打开候选。拦截反馈提示脱敏，但缺少接得上的入口。 | P0。将粘贴、选文件、定位、复核和复制放在一个本地窗口中，给两端的提示词拦截提供相同入口。 |
| 安装与更新 | Skill、两种客户端插件和邮箱实验都出现在首页介绍里。Claude 的安装脚本忽略自定义配置目录。ZIP 冲突会留下半成品。 | P0。首页先给无插件流程，修复自定义目录和打包回滚。下一步提供可下载的版本包，并做首次安装计时。 |
| 有些普通输入被误拦 | 未列入规则的站点链接会命中 URL，数字串可命中卡号或电话。现有规则依赖结构、格式与有限的公共链接允许条件。 | P1。先建一套同一版本可复跑的正负样本，分别统计误拦与漏检；将常见公共文档路径和工程编号作为对照。覆盖令牌、签名、内网、混合编码和误配路径后，再评估是否扩展精确放行条件。 |
| 地址、姓名和业务秘密 | 结构化高敏类型能命中部分格式，未配置的名字、地址和上下文组合可能通过。疑点目前主要来自已知标签。 | P1。保持默认策略，收集虚构联系单、表单、日志、双语消息和技术工单的样本。按数据类型比较误检、漏检和多余复核，优先新增高精度信号。 |
| 普通敏感类型和词典的长期维护 | 普通类型选择写在 JSON，词典按宿主分别维护。无效配置需要到文件里定位。 | P1。增加本地设置入口，每类只设置一次，显示当前启用的类型和配置校验结果。高敏规则始终执行，日常遇到命中时无需再次选类型。 |
| 已安装却没运行 | 配置自检能提示未验证，无法证明当前聊天的 Hook 已执行。宿主跳过 Hook 仍有覆盖缺口。 | P1。下一步做一次性的当前会话合成验收和低频状态提示。重要输入可以直接用独立预检。 |
| PDF、截图、附件和目录读取 | 不同宿主有自己的上传路径，文本脱敏规则只处理支持的材料。 | P2。先验证 PDF 文本层的本地提取、页码定位和导出；扫描件单独验证 OCR。目录读取继续依赖具体工具的访问范围。 |
| 要把真实值填入指定网站 | 注册实验仅支持虚构邮箱和回环测试站点，线上授权需要单独验证。 | P2。普通用户的预检流程不依赖这项实验。 |

推荐默认路径是普通聊天按原来的方式使用，敏感文本在本机先预检，插件提供额外检查。优先为被拦截的少数消息缩短恢复路径。新一轮检测规则应以每类样本的误拦、漏检与人工复核量为验收指标。在没有代表性样本之前，不宣称达到某个总体覆盖率。

建议用没有安装过项目的用户做一次冷启动测试，记录打开预检、成功复核第一个合成样例、找到一次拦截原因分别要花多久。非中文界面和 Windows 安装也应独立验收，再纳入正式支持范围。

## 实施步骤

1. 在干净工作区跑基线测试，核对已有的结构化处理、插件、包和本地预览入口。
2. 对比本地 GUI 方案。复用 Python 检测内核，添加独立回环页面。页面仅传递文字、格式、允许的词典选项，服务端没有任意路径读取或修改设置的入口。用户手动复制或下载时才导出候选。
3. 合并两端的打包清单，给提示词拦截增加明确打开方式。记录安装和打包的复现条件，并加回归覆盖。
4. 验证正常消息、公开链接、虚构敏感文本、JSON/Markdown 内容和换行、失效候选、回环边界、两个安装包与客户端的现有 Hook 契约。

## 踩坑与修复

| 复现 | 原因 | 处理 |
| --- | --- | --- |
| Tk 可以 import，但启动窗口在本机默认 Python 退出，另一套 Python 则出现 Tk 初始化失败。 | 仅检查模块存在不能证明系统图形依赖能初始化。沙箱也限制了本机 GUI 服务。 | 使用系统浏览器和 Python 标准库，浏览器测试跑真实页面。 |
| 选中 CRLF 文件后，把文本框的值交给后端，换行可能已被浏览器改为 LF。 | 文本框会规范化换行。 | 文件原文在内存保留，编辑后才取文本框内容，下载使用服务端候选原始内容。 |
| 生成后改动输入或选择新的策略，旧候选可能仍可复制，旧请求也可能迟到。 | 输入与候选有版本依赖。 | 改动立即清除候选，并按生成序号丢弃旧响应。 |
| 已有同名 ZIP、目标目录不存在时，旧脚本先创建目录，后因 ZIP 冲突退出。 | 目录和归档的创建顺序没有失败清理。 | 以独占方式创建归档，回滚本次创建的输出，保留已有文件。 |
| 用 `plugin-0.2.6` 作输出目录，旧脚本生成 `plugin-0.2.zip`。 | 路径处理把版本号的最后一段当成扩展名。 | 在目录名后追加 `.zip`，保留完整版本号，加入打包回归。 |
| 以自定义 `CLAUDE_CONFIG_DIR` 运行安装器，Skill 仍写到默认目录。 | Claude 分支未读取该变量。 | 两个宿主都按对应配置目录解析，并验证自定义路径。 |
| 基线测试中的 Unix socket `bind` 在默认沙箱返回 `Operation not permitted`。 | 测试需要本地 socket，默认执行环境禁止绑定。 | 使用授权范围内的隔离测试执行，保持 socket 测试断言。验证记录见仓库根目录 `VALIDATION.md`。 |
| PATH 上的 Claude Code 启动入口在原生测试中无法执行。 | npm 入口解析到本机无法执行的目标，故障发生在运行项目代码前。 | 换用桌面随附的可执行文件，在同一隔离配置中复验，无需修改用户的 CLI 安装。 |
| 本地提交自动生成的身份带有机器名。 | 此工作区依赖 Git 对本机用户名和主机名的推断。 | 在提交时沿用仓库上一次提交的身份，核对提交元数据，避免把机器名带入公开仓库。 |
